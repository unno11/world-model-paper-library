# Optical Flow：用像素运动理解视频变化

光流（Optical Flow）是图像序列中像素表观运动的估计。它通常为每个像素提供一个二维位移向量，帮助模型理解物体运动、相机运动、碰撞和动作阶段。

本文重点负责光流的直觉、表示、估计、验证和在机器人/视频中的用途；视频整体建模见 [[视频理解]]，视觉特征见 [[视觉表征]]，图像和 Tensor shape 见 [[图像基础]]、[[PyTorch]]。

## 0. 学习目标

学完以后能够：

- 区分光流、光流场、运动向量和真实三维运动；
- 解释相邻帧如何产生像素位移；
- 读懂光流的 shape、单位、方向和可视化；
- 理解亮度恒常、平滑和遮挡等基本问题；
- 看懂光流作为视频/机器人输入的代码；
- 排查坐标方向、尺度、时间间隔和遮挡错误。

## 1. 为什么需要光流？

单张图像描述“现在看到什么”，光流提供“画面中什么在如何变化”。

```text
帧 I_t
↓
与下一帧 I_{t+1} 比较
↓
估计每个像素的位移 (u,v)
↓
光流场
↓
运动分割 / 动作识别 / 机器人控制
```

它可能帮助判断物体接近、手臂运动方向、相机是否移动以及场景动态区域。

## 2. 核心概念

### 2.1 光流场（Flow Field）

光流场是一个二维向量场。对 H×W 图像，常见表示为 [H,W,2]：

- 最后一维 2：水平位移 u 和垂直位移 v；
- u>0 常表示向右；
- v>0 常表示向下；
- 具体坐标约定必须查看代码。

批量形式可能是 [B,2,H,W] 或 [B,H,W,2]。

### 2.2 表观运动与真实运动

光流描述的是图像亮度模式的表观移动，不直接等于物体在三维世界中的速度。相机运动、光照变化、纹理缺失和遮挡都会影响估计。

### 2.3 亮度恒常假设

经典光流常假设同一物体点在相邻帧亮度近似不变：

$$
I(x,y,t) \approx I(x+u,y+v,t+1)
$$

真实场景中光照、反射和曝光可能违反该假设。

### 2.4 稠密与稀疏光流

- 稠密光流：每个像素估计一个向量；
- 稀疏光流：只跟踪关键点或特征点。

稠密信息丰富但计算量大；稀疏方法更轻量但覆盖有限。

### 2.5 光流可视化

常把方向映射为色调，把速度大小映射为饱和度/亮度。颜色环不是天然语义，必须配合 legend 或已知运动样例校验。

## 3. 光流的整体工作原理

```text
I_t 与 I_{t+1}
↓
特征匹配或神经网络估计
↓
flow [H,W,2]
↓
warp / endpoint error / motion mask
↓
视频理解或控制模块
```

warp 可以按 flow 将一帧采样到另一帧，但边界、遮挡和采样方式需要特别处理。

## 4. 从零读懂光流张量

```python
flow = torch.randn(4, 2, 128, 192)
u = flow[:, 0]
v = flow[:, 1]
magnitude = torch.sqrt(u**2 + v**2)

print(flow.shape)       # [B,2,H,W]
print(magnitude.shape)  # [B,H,W]
```

如果代码用 [B,H,W,2]，取分量的方式会不同。不要只看最后一行，先确认布局。

### 4.1 速度大小与方向

$$
magnitude=\sqrt{u^2+v^2}
$$

方向可用 atan2(v,u)。运动大小和方向常被分别送入后续模块。

## 5. Flow 的评估

常见指标：

- Endpoint Error（EPE）：预测向量与真实向量的欧氏距离；
- 角度误差；
- 运动区域 IoU；
- 下游动作/视频任务指标。

光流真值通常来自合成数据、传感器或标注，不是所有真实视频都有可靠 ground truth。见 [[模型评估]]。

## 6. 光流与视频理解

光流可以作为：

- RGB 之外的运动输入；
- 动作识别特征；
- 视频帧配准和跟踪线索；
- 相机运动估计辅助；
- 机器人接近、碰撞和运动阶段判断；
- World Model 中的动态辅助目标。

典型融合：

```text
RGB frame encoder
+
flow encoder
+
proprioception
↓
temporal model / Transformer
↓
action or future prediction
```

光流不是视频理解的全部：物体身份、语义和长期目标仍需要外观与时序表示。

## 7. 在具身智能中的使用

机器人可能利用 flow：

- 判断末端执行器相对物体的运动；
- 估计接近速度；
- 识别抓取后物体是否移动；
- 从相机运动中推断导航变化；
- 作为视觉伺服的误差信号。

真实闭环中要考虑控制频率、帧时间间隔、相机曝光、动态障碍和光流延迟。

## 8. 常见错误与 Debug

### 8.1 u/v 方向反了

检查一个已知向右移动的物体，确认 u 符号；检查坐标原点和图像 y 方向。

### 8.2 flow 单位混淆

flow 可能是像素位移、归一化坐标位移或相邻帧速度。必须结合分辨率和 dt 判断，不能直接比较不同帧率的数据。

### 8.3 HWC/CHW 与 flow layout 混淆

图像常是 [B,C,H,W]，flow 也可能是 [B,2,H,W]；可视化库可能期待 [H,W,2]。显式转换并打印。

### 8.4 遮挡区域仍被强行解释

遮挡没有对应像素，flow 可能不可靠。使用 occlusion mask、置信度或 forward-backward consistency。

### 8.5 大位移无法匹配

相邻帧间隔太大或运动太快，传统局部方法可能失败。降低时间间隔、使用多尺度估计或检查相机运动。

### 8.6 光照变化造成假运动

亮度变化可能被当成运动。结合 RGB、梯度、置信度和环境条件判断。

## 9. 容易混淆

| 概念 | 含义 | 不等于 |
|---|---|---|
| optical flow | 图像表观运动 | 三维速度 |
| u/v | 水平/垂直位移 | x/y 世界坐标 |
| magnitude | 运动大小 | 速度一定正确 |
| dense flow | 每像素向量 | 关键点轨迹 |
| occlusion | 没有对应可见点 | 静止 |
| warp | 按位移重采样 | 完整三维变换 |
| camera motion | 相机导致的全局变化 | 物体运动 |

## 13. 练习题（题目下附参考答案）

1. 光流描述什么？

**参考答案：** 描述图像序列中像素或亮度模式的表观位移。

2. 光流向量通常有几维？

**参考答案：** 2 维，水平 u 和垂直 v。

3. [B,2,H,W] 中 2 表示什么？

**参考答案：** 水平和垂直位移分量。

4. 光流等于三维真实速度吗？

**参考答案：** 不等于，它是图像平面上的表观运动，受相机、深度、光照和遮挡影响。

5. 稠密光流与稀疏光流区别是什么？

**参考答案：** 稠密估计每像素，稀疏只估计关键点或特征点。

6. u=3、v=4 时 magnitude 是多少？

**参考答案：** 5，因为 sqrt(3²+4²)=5。

7. 如何验证 u 的方向？

**参考答案：** 用已知向右移动的物体检查 u 符号，并确认图像坐标约定。

8. 为什么要关注 dt？

**参考答案：** 同样的像素位移在不同帧间隔下对应不同速度，flow 的物理解释依赖时间间隔。

9. flow 为什么可能在遮挡处不可靠？

**参考答案：** 遮挡后没有可对应的可见像素，无法稳定估计位移。

10. EPE 衡量什么？

**参考答案：** 预测光流向量与真值向量的欧氏距离。

11. 光流如何帮助动作识别？

**参考答案：** 提供运动方向和速度变化，补充静态 RGB 外观。

12. 光流作为机器人输入前要检查什么？

**参考答案：** layout、符号、单位、帧间隔、置信度、相机运动和延迟。

13. [B,H,W,2] 转 [B,2,H,W] 的思路是什么？

**参考答案：** 交换最后通道维与空间维，使用 permute/transpose，不能 reshape。

14. 颜色变化为什么会造成假光流？

**参考答案：** 光流方法可能把亮度模式变化解释为像素运动。

15. 大位移光流失败时怎么处理？

**参考答案：** 缩短帧间隔、使用多尺度/更强估计器，并检查相机运动和纹理。

16. forward-backward consistency 可帮助什么？

**参考答案：** 检测遮挡、匹配不一致或不可靠的光流区域。

17. flow 与 RGB 如何融合？

**参考答案：** 分别编码后拼接/交叉融合，或把 flow 作为额外通道，但要匹配统计和时间。

18. 视觉伺服中光流可作为什么？

**参考答案：** 运动误差、接近速度或相对运动线索。

19. World Model 训练中加入 flow 目标有什么价值？

**参考答案：** 提供动态变化的辅助监督，帮助表示关注运动和未来变化。

20. 研究代码中看到 flow，先查什么？

**参考答案：** 数据来源、单位、shape、帧时间间隔、mask、可视化和下游使用。

## 13. 掌握度检查（附答案）

1. 光流与图像的关系是什么？

**答案：** 它从相邻图像估计像素/亮度模式在图像平面上的位移。

2. flow 的两个分量是什么？

**答案：** 水平位移 u 和垂直位移 v。

3. flow layout 为什么重要？

**答案：** [B,2,H,W] 和 [B,H,W,2] 的索引语义不同，错误可能不立即报错。

4. magnitude 表示什么？

**答案：** 位移向量的欧氏长度，表示表观运动大小。

5. 光流为什么不等于真实三维速度？

**答案：** 图像投影、深度、相机运动和遮挡都会影响像素运动。

6. 亮度恒常是什么假设？

**答案：** 同一物体点在相邻帧的亮度近似保持不变。

7. 遮挡为什么需要 mask？

**答案：** 遮挡区域没有可靠对应点，不能把估计当成正常监督。

8. EPE 是什么？

**答案：** 预测与真值光流向量之间的端点欧氏误差。

9. 光流在视频理解中的价值是什么？

**答案：** 提供动态变化线索，弥补单帧外观不足。

10. 机器人使用 flow 的风险是什么？

**答案：** 延迟、光照、相机运动、纹理缺失、单位和帧率差异可能导致控制错误。

11. 为什么要可视化 flow？

**答案：** 验证方向、大小、布局、遮挡和异常区域。

12. flow 作为 World Model 辅助目标说明什么？

**答案：** 训练希望表示包含动态和未来变化信息。

13. 何时查 [[视频理解]]？

**答案：** 需要把 flow 与帧级外观、时间模型和动作语义结合时。

14. 何时查 [[图像基础]]？

**答案：** 需要检查图像坐标、通道、shape 和预处理时。

15. 读光流代码最先检查哪五项？

**答案：** shape/layout、单位、u/v 方向、dt、mask/置信度。
