# 优化器：如何用梯度更新模型参数

优化器是训练循环中真正执行参数更新的组件。损失函数告诉我们目标是什么，autograd 计算梯度，优化器根据梯度、学习率和内部状态决定参数怎么变化。

```text
loss
    ↓ backward
parameter.grad
    ↓ optimizer
parameter_new
```

常见 PyTorch 代码：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

这三行背后涉及微积分、优化和工程状态。数学基础见 [[优化]] 和 [[微积分]]；训练整体见 [[PyTorch]]。

## 0. 学习目标

学完以后，应该能够：

- 区分参数、梯度、优化器状态和超参数。
- 解释 SGD、Momentum、Adam 和 AdamW 的基础直觉。
- 理解 learning rate、batch、step、epoch。
- 读懂 zero_grad、backward、step 的顺序。
- 理解 optimizer 为什么需要 model.parameters。
- 认识 scheduler、weight decay、gradient clipping。
- 根据 loss、梯度和参数变化 Debug 优化问题。
- 在监督学习、行为克隆和 World Model 中合理记录优化设置。

## 1. 为什么需要优化器？

模型参数很多，不能手动逐个修改。优化器把梯度转成参数更新：

```text
当前参数 θ
    ↓
loss 对 θ 的梯度
    ↓
优化规则
    ↓
新的 θ
```

最简单的梯度下降：

```text
θ_new = θ_old - learning_rate × gradient
```

真实优化器还可能保存动量、梯度平方的平均值和权重衰减等状态。

## 2. 核心概念

### 2.1 Parameters

模型中的可学习权重和偏置是 parameters。只有交给 optimizer 的参数才会被它更新。

```python
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
```

如果模型有一个子模块但没有正确注册，optimizer 可能拿不到它的参数。

### 2.2 Gradients

gradient 描述 loss 对参数的局部变化。backward 后通常保存在 parameter.grad。

### 2.3 Optimizer state

SGD with momentum、Adam 等优化器会保存历史信息。它不是模型参数，但恢复训练时可能很重要。

### 2.4 Hyperparameters

学习率、momentum、weight decay、betas 等是超参数，通常由研究者选择或调节，不是通过当前 loss 直接学习出来的模型参数。

## 3. SGD

### 3.1 基本公式

```text
θ ← θ - η ∇L(θ)
```

- η 是 learning rate。
- ∇L 是当前 batch 梯度。

### 3.2 Mini-batch SGD

深度学习常用小批量梯度：

```text
用当前 batch 估计整体梯度
    ↓
更新一次参数
```

因为每个 batch 不完全相同，loss 和梯度带有噪声。单 step 不下降不一定是错误。

### 3.3 SGD 参数

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
)
```

SGD 简单、可解释，但可能需要较多调参。

## 4. Momentum

Momentum 维护历史方向，减少在狭长谷底中的来回振荡：

```text
当前梯度
    + 历史更新方向
    ↓
更平滑的参数移动
```

```python
optimizer = torch.optim.SGD(
    model.parameters(),
    lr=0.01,
    momentum=0.9,
)
```

momentum 不是“让模型记住所有数据”，而是优化器的更新状态。

## 5. Adam 与 AdamW

### 5.1 Adam 直觉

Adam 同时追踪：

- 梯度的一阶移动平均，表示方向趋势。
- 梯度平方的移动平均，表示尺度趋势。

然后为不同参数调整有效步长。

```python
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=1e-3,
)
```

### 5.2 AdamW 与 weight decay

AdamW 常用于把 weight decay 与 Adam 的梯度更新分开处理：

```python
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=1e-4,
    weight_decay=1e-2,
)
```

Adam、AdamW 不是自动保证最优的选择。模型、数据、batch、学习率和 loss 仍然决定结果。

## 6. zero_grad、backward、step

标准更新：

```python
optimizer.zero_grad(set_to_none=True)
prediction = model(x)
loss = loss_fn(prediction, target)
loss.backward()
optimizer.step()
```

### 6.1 zero_grad

PyTorch 默认累积梯度。zero_grad 清理上一轮梯度。

### 6.2 backward

backward 沿计算图计算 loss 对参数的梯度，见 [[微积分]]。

### 6.3 step

step 使用当前梯度和优化器状态更新参数。

顺序错误会导致：

- 没有清理梯度。
- step 时没有新梯度。
- 使用旧计算图或错误参数。
- 梯度累计方式与预期不一致。

## 7. batch、step 与 epoch

- batch：一次输入的一组样本。
- step：通常一次 optimizer.step。
- epoch：遍历训练集一次。
- gradient accumulation：多个 batch 计算梯度后再 step。

```python
for epoch in range(num_epochs):
    for batch in loader:
        optimizer.zero_grad()
        loss = compute_loss(batch)
        loss.backward()
        optimizer.step()
```

如果设置梯度累积，zero_grad 和 step 的位置要有意识地改变。

## 8. 学习率与调度器

### 8.1 学习率过大/过小

- 太大：loss 振荡、发散、NaN。
- 太小：loss 几乎不动，训练过慢。
- 合适：整体下降，验证表现改善。

### 8.2 Scheduler

scheduler 根据 step 或 epoch 改变 learning rate：

```python
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer,
    T_max=100,
)

for epoch in range(100):
    train_one_epoch()
    scheduler.step()
```

不同 scheduler 的调用时机不同。阅读仓库时要确认 scheduler.step 是按 batch 还是按 epoch 调用。

### 8.3 记录有效学习率

```python
for group in optimizer.param_groups:
    print(group["lr"])
```

多参数组可能有不同学习率，不能只记录一个手写配置值。

## 9. Weight Decay 与正则化

weight decay 让参数更新有缩小倾向，常用于控制模型复杂度和过拟合。

它不是：

- 直接把所有参数变为 0。
- 删除模型层。
- 代替数据增强或验证集。
- 对所有参数都应同样使用的规则。

正则化系统内容见 [[正则化]]。

## 10. 梯度裁剪与混合精度

### 10.1 梯度裁剪

当梯度过大时，可以限制梯度范数：

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
optimizer.step()
```

裁剪可以缓解爆炸，但不能代替寻找异常输入或错误 loss。

### 10.2 混合精度

混合精度用不同精度执行部分计算，以减少显存和提升速度。它可能需要 autocast 和 GradScaler 等机制。

当前阶段知道：

- 混合精度改变数值计算方式。
- 可能出现 underflow/overflow。
- Debug 时先用简单精度和小模型验证逻辑。

## 11. 参数组（Parameter Groups）

不同模块可能使用不同学习率：

```python
optimizer = torch.optim.AdamW([
    {"params": model.encoder.parameters(), "lr": 1e-5},
    {"params": model.head.parameters(), "lr": 1e-3},
])
```

这在微调预训练 encoder、训练新 head 时常见。要确认：

- 参数没有重复加入。
- 冻结模块是否真的 requires_grad=False。
- 每组学习率和 weight decay 是否符合实验意图。

## 12. 优化器与不同 AI 任务

### 12.1 视觉分类

常见设置是 AdamW 或 SGD，loss 为交叉熵，评估准确率和其他分类指标。

### 12.2 行为克隆

动作回归可能使用 MSE/Huber，动作尺度、学习率和多维动作权重很重要。

### 12.3 World Model

可能同时优化状态预测、reward、重建或 latent loss。优化器看到的是总 loss 的梯度，不知道每个子任务的科学意义，因此需要记录每个分项。

## 13. 常见错误与 Debug

### 13.1 参数不更新

- **现象**：step 后参数完全不变。
- **检查**：optimizer 是否拿到正确参数，requires_grad、grad、step 是否执行。
- **处理**：比较 step 前后参数，打印 optimizer.param_groups。
- **原因**：参数可能被冻结、计算图断开或使用了错误模型实例。

### 13.2 loss 发散

- **现象**：loss 越来越大或 NaN。
- **检查**：学习率、输入尺度、梯度范数、loss、异常 batch。
- **处理**：先缩小实验，确认数据和 loss，再调整学习率或梯度裁剪。

### 13.3 忘记 zero_grad

- **现象**：梯度越来越大，训练行为异常。
- **检查**：zero_grad 调用位置和是否故意使用梯度累积。
- **处理**：默认每次更新前清零；若累积，明确记录 accumulation steps。

### 13.4 scheduler 时机错误

- **现象**：实际学习率与预期不符。
- **检查**：打印每个 epoch/step 的 lr，确认 scheduler.step 的位置。
- **处理**：按照 scheduler 和仓库说明统一调用粒度。

### 13.5 恢复训练结果不一致

- **现象**：加载 checkpoint 后曲线不同。
- **原因**：只保存模型没保存 optimizer/scheduler、随机状态、epoch 或数据顺序。
- **处理**：保存完整训练状态和实验元信息。

## 17. 练习题（题目下附参考答案）

### Level 1：概念

1. 优化器和损失函数分别负责什么？
   
   **参考答案：**损失函数定义预测好坏，优化器根据损失产生的梯度和规则更新参数。

2. 梯度、参数和优化器状态有什么区别？
   
   **参考答案：**参数是被学习的值；梯度是当前 loss 对参数的变化信息；优化器状态是动量、梯度统计等更新所需历史信息。

3. 学习率是什么？
   
   **参考答案：**学习率控制每次根据梯度移动的步长，是重要超参数。

### Level 2：判断

4. 判断：optimizer.step 会自动计算梯度。
   
   **参考答案：**错误。通常需要先调用 loss.backward 计算梯度，step 再使用梯度。

5. 判断：zero_grad 可以省略，因为 PyTorch 会自动覆盖旧梯度。
   
   **参考答案：**错误。梯度默认累积，除非明确采用梯度累积策略，否则应清零。

6. 判断：Adam 一定比 SGD 更好。
   
   **参考答案：**错误。优化器效果取决于任务、模型、数据和超参数，没有永远最好的选择。

7. 判断：weight decay 会把所有参数直接变成零。
   
   **参考答案：**错误。它是一种参数正则化倾向，不是直接清零。

### Level 3：读代码

8. 逐行解释标准训练更新。

   ```python
   optimizer.zero_grad()
   loss = loss_fn(model(x), target)
   loss.backward()
   optimizer.step()
   ```

   **参考答案：**先清除旧梯度；执行 forward 和 loss；反向传播计算梯度；使用梯度更新参数。

9. 为什么要打印 optimizer.param_groups？
   
   **参考答案：**确认优化器实际管理了哪些参数组，以及每组真正使用的学习率和其他设置。

10. gradient clipping 应放在哪里？
    
    **参考答案：**通常在 loss.backward 之后、optimizer.step 之前，因为它要限制刚计算出的梯度。

11. scheduler.step 的时机为什么重要？
    
    **参考答案：**有的调度器按 epoch 更新，有的按 step 更新；位置错误会让实际学习率曲线与设计不符。

### Level 4：应用

12. 什么时候可能给 encoder 和 head 设置不同学习率？
    
    **参考答案：**微调预训练 encoder、训练新 head 时，通常希望 encoder 小幅更新、head 快速学习。

13. 如何判断一次更新是否真的改变了参数？
    
    **参考答案：**在 step 前复制参数，step 后比较；同时检查 grad 和 optimizer 是否包含该参数。

14. 为什么行为克隆要关注动作尺度？
    
    **参考答案：**不同动作维度的尺度会影响 loss 和梯度，某一维可能主导优化，需要归一化或加权。

### Level 5：Debug

15. loss 不下降，优化器排查顺序是什么？
    
    **参考答案：**确认 optimizer 管理正确参数 → 确认 backward 有 grad → 确认 step 执行 → 检查学习率 → 检查输入、loss 和标签。

16. loss 发散时，检查哪些优化相关量？
    
    **参考答案：**实际学习率、梯度范数、参数变化、输入范围、loss 分项、scheduler 和优化器状态。

17. 恢复 checkpoint 后训练不一致，优化器方面可能缺什么？
    
    **参考答案：**可能缺少 optimizer.state_dict、scheduler 状态、当前 epoch、学习率和随机状态。

### Level 6：综合科研场景

18. 设计一个 AdamW 与 SGD 的公平比较。
    
    **参考答案：**固定数据、模型、split、训练预算和 seed 集合，分别调试但记录学习率和 weight decay，比较验证/测试指标、收敛曲线和稳定性。

19. 一个多任务 World Model 的总 loss 不降，如何拆解优化问题？
    
    **参考答案：**分别记录每个分项 loss、梯度和尺度，确认权重、数据、参数组和学习率；先用小数据验证每个任务能否单独学习。

20. 设计一份优化器实验记录。
    
    **参考答案：**记录优化器类型、学习率、batch、epoch/step、momentum/betas、weight decay、scheduler、梯度裁剪、seed、代码 commit、loss 曲线和 checkpoint。

## 18. 掌握度检查（附答案）

1. 优化器做什么？
   
   **答案：**根据参数梯度、学习率和内部状态更新模型参数。

2. 为什么优化器需要 model.parameters？
   
   **答案：**它需要知道哪些 Tensor 是要被更新的参数。

3. zero_grad、backward、step 的关系是什么？
   
   **答案：**清除旧梯度 → 计算当前梯度 → 使用梯度更新参数。

4. SGD 的核心更新是什么？
   
   **答案：**参数减去学习率乘以梯度。

5. Momentum 的直觉是什么？
   
   **答案：**利用历史更新方向平滑和加速当前移动。

6. Adam 的直觉是什么？
   
   **答案：**追踪梯度方向和尺度的移动统计，为不同参数调整有效步长。

7. 学习率太大或太小分别可能怎样？
   
   **答案：**太大可能振荡、发散；太小可能训练慢或几乎不动。

8. scheduler 解决什么问题？
   
   **答案：**按 step 或 epoch 计划改变学习率，以适应训练不同阶段。

9. weight decay 与正则化有什么关系？
   
   **答案：**weight decay 对参数施加缩小倾向，是常见正则化机制之一。

10. 为什么要检查参数前后是否变化？
    
    **答案：**它能验证梯度、optimizer 参数管理和 step 是否真正连通。

11. 什么是优化器状态？
    
    **答案：**保存动量、梯度统计和其他更新所需历史信息的状态。

12. 梯度裁剪什么时候有用？
    
    **答案：**梯度过大或训练不稳定时可以限制梯度范数，但不能替代根因排查。

13. 优化器如何连接到损失函数？
    
    **答案：**loss 通过 backward 产生梯度，优化器使用这些梯度更新参数。

14. 优化器如何连接到模型评估？
    
    **答案：**优化器只直接优化训练目标，模型评估需要独立 validation/test 指标判断泛化。

15. 怎样判断自己掌握了本篇？
    
    **答案：**能够读懂 optimizer 初始化和训练更新，解释学习率、状态、scheduler，并能排查参数不更新和 loss 发散。
